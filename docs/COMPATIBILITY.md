# Complete PCNTL API audit for Windows

Target: the full conditional set of 34 function names declared by PHP 8.5's ext/pcntl/pcntl.stub.php. An exported function does not mean complete POSIX semantics.

## Native process operations

- pcntl_waitpid: implemented for child processes returned by pcntl_windows_spawn, PID or -1; WNOHANG supported. PID 0 and negative process groups not implemented.
- pcntl_wait: implemented for registered request-local child handles; any-child waits poll handles without the Win32 64-handle limit.
- pcntl_waitid: implemented for P_PID / P_ALL with WEXITED, WNOHANG and WNOWAIT; no stopped/continued events or POSIX UID semantics.
- pcntl_wifexited, pcntl_wexitstatus: implemented POSIX-style status decoding; Windows process exit codes truncated to 8 bits.
- pcntl_wifstopped, pcntl_wifsignaled, pcntl_wstopsig, pcntl_wtermsig, pcntl_wifcontinued: status decoders are exported but no native Unix stop/signal/continue state is generated by Windows process waiting.
- pcntl_get_last_error, pcntl_errno, pcntl_strerror: implemented using CRT-style errors and a finite Win32 error mapping.

## Scheduling

- pcntl_getpriority, pcntl_setpriority: exposed, limited to PRIO_PROCESS and coarse Windows priority-class mapping. The setter never chooses REALTIME_PRIORITY_CLASS.
- pcntl_getcpuaffinity, pcntl_setcpuaffinity: exposed, restricted to the processor group represented by GetProcessAffinityMask. Not a full multi-group CPU Sets implementation.
- pcntl_getcpu: exposed; CPU numbers are processor-group-relative.
- pcntl_getqos_class, pcntl_setqos_class: exposed using Windows thread priorities and a native Pcntl\QosClass enum; not equivalent to Darwin QoS scheduling.

## Cooperative signals

- pcntl_signal: exported for selected extension-managed signals, console controls, and registered Windows-child SIGCHLD notifications; no arbitrary POSIX process-wide signal delivery.
- pcntl_signal_get_handler, pcntl_signal_dispatch: exported for registered PHP callbacks on the execution thread.
- pcntl_async_signals: exported, integrates queued events through Zend VM interrupts for one active CLI request.
- pcntl_sigprocmask: exported for extension-managed signals only; not a kernel thread signal mask.
- pcntl_sigwaitinfo, pcntl_sigtimedwait: exported, consume the cooperative event queue, not POSIX siginfo from the kernel. Timeout resolution is in milliseconds.
- pcntl_alarm: exported, schedules Win32 timer events. Without async dispatch, PHP handlers are invoked on an explicit pcntl_signal_dispatch call.

## Not exported: requirements for genuine support

- pcntl_fork: requires continuing in both parent and child from the same C/PHP instruction with copied address space, heap, stack and resources. CreateProcessW is not a fork. A Cygwin-style runtime port or dedicated PHP runtime cooperation is required.
- pcntl_exec: POSIX exec replaces the current process image while preserving identity; ordinary Windows process creation makes a new PID. A supervisor handoff is a different contract.
- pcntl_forkx: Solaris-specific semantics and flags need a Solaris implementation or separately defined equivalent.
- pcntl_rfork: BSD-specific process and resource-sharing flags need a compatible BSD runtime.
- pcntl_unshare: Linux kernel namespace creation needs a Linux execution context for its guarantees.
- pcntl_setns: joining existing Linux kernel namespaces needs a Linux execution context; native Windows jobs, silos and containers do not transparently join Linux namespaces.

## Quality gates

1. Every new canonical PCNTL function must retain its documented PHP argument and return types.
2. Require a PHPT test demonstrating real Windows behavior and failure cases.
3. Compare result semantics to POSIX reference tests where relevant; label unavoidable divergence clearly.
4. Build and run PHPT on PHP 8.4 and 8.5, TS and NTS, x86 and x64.
5. Never export pcntl_fork as a CreateProcessW wrapper or a no-op. Do not fake namespace isolation or thread security guarantees.

## Alternate native POSIX runtime validation

- WSL2 Linux PHP: real fork/exec conformance is covered by tests/reference/fork-exec.php; Linux namespace capabilities are probed separately and depend on privileges.
- FreeBSD PHP: rfork is tested in tests/reference/rfork.php on a FreeBSD VM.
- Solaris/illumos PHP: forkx is tested in tests/reference/forkx.php on a Solaris VM when available.
- macOS PHP: Apple QoS is validated in tests/reference/darwin-qos.php.
- Native Win32 helpers pcntl_windows_spawn, pcntl_windows_terminate and pcntl_windows_raise are not upstream PCNTL functions and must not be confused with true Unix process semantics.
