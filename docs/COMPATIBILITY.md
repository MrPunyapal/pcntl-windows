# Complete PCNTL API audit for Windows

Target: the full conditional set of 34 function names declared by PHP 8.5's ext/pcntl/pcntl.stub.php. An exported function does not mean complete POSIX semantics.

at `3bb1ccb`: **35 passed, zero failed, one unsafe-clone test skipped per
configuration** ([run 42878288902](https://github.com/MrPunyapal/pcntl-windows/actions/runs/42878288902)).

### Remaining API-level differences

The function inventory below is not an assertion of exact argument/error parity.
Beyond the platform limitations described per function:

- Cooperative signal callbacks currently receive the signal number only, without
  upstream kernel `siginfo` as a second argument. Signal arrays require supported
  integer identifiers; upstream accepts some coercible values. Empty BLOCK/UNBLOCK
  arrays are accepted locally, although upstream rejects them. Empty SETMASK is
  supported by both.
- Successful native operations generally clear `last_error`; upstream commonly
  retains the previous error. The native timed-wait timeout sets `EAGAIN`, while
  current upstream PHP returns false without updating its stored error for that
  timeout. Do not use identical errno histories as a cross-runtime guarantee.
- Native `waitid(WNOHANG)` emits empty output arrays when nothing is ready.
  POSIX `siginfo` fields, UID accounting, stopped/continued events and full
  resource-usage fields are not synthesized.
- Native priority input is restricted to -20..19 and mapped into coarse Win32
  classes; Unix kernel clamping, permission errors and warning text differ.
- Win32 syscall failures are mapped to a finite CRT errno set. Warning and
  exception behavior is not yet identical for every POSIX failure case.

These remain compatibility gaps, not passing conformance claims or reasons to
substitute fake Unix operations. The native module remains experimental.

## Native process operations

- pcntl_waitpid: implemented for child processes returned by pcntl_windows_spawn, PID, -1, PID 0 (default children), and negative group IDs for registered Win32 children created with new_process_group=true; WNOHANG supported. This tracks extension-owned process groups only, not arbitrary POSIX groups.
- pcntl_wait: implemented for registered request-local child handles; any-child waits use threadpool event notifications and scan registered handles without the Win32 64-handle limit. If wait registration fails, a polling fallback remains.
- pcntl_waitid: implemented for P_PID / P_ALL / P_PGID (registered Win32 child groups) with WEXITED, WNOHANG and WNOWAIT; no stopped/continued events or POSIX UID semantics.
- pcntl_wifexited, pcntl_wexitstatus: implemented POSIX-style status decoding; Windows process exit codes truncated to 8 bits.
- pcntl_wifstopped, pcntl_wifsignaled, pcntl_wstopsig, pcntl_wtermsig, pcntl_wifcontinued: status decoders are exported but no native Unix stop/signal/continue state is generated by Windows process waiting.
- pcntl_get_last_error, pcntl_errno, pcntl_strerror: implemented using CRT-style errors and a finite Win32 error mapping.

## Scheduling

- pcntl_getpriority, pcntl_setpriority: exposed, limited to PRIO_PROCESS and coarse Windows priority-class mapping. The setter never chooses REALTIME_PRIORITY_CLASS.
- pcntl_getcpuaffinity, pcntl_setcpuaffinity: exposed, restricted to the processor group represented by GetProcessAffinityMask. Not a full multi-group CPU Sets implementation.
- pcntl_getcpu: exposed; CPU numbers are processor-group-relative.
- pcntl_getqos_class, pcntl_setqos_class: exposed using Windows thread priorities and a native Pcntl\QosClass enum; not equivalent to Darwin QoS scheduling.

## Cooperative signals

- pcntl_signal: exported for selected extension-managed signals, console controls, and registered Windows-child SIGCHLD notifications; no arbitrary POSIX process-wide signal delivery.
- pcntl_signal_get_handler, pcntl_signal_dispatch: exported for registered PHP callbacks on the execution thread.
- pcntl_async_signals: exported, integrates queued events through Zend VM interrupts for one active CLI request.
- pcntl_sigprocmask: exported for extension-managed signals only; not a kernel thread signal mask.
- pcntl_sigwaitinfo, pcntl_sigtimedwait: exported, consume the cooperative event queue, not POSIX siginfo from the kernel. Timeout resolution is in milliseconds.
- pcntl_alarm: exported, schedules Win32 timer events. Without async dispatch, PHP handlers are invoked on an explicit pcntl_signal_dispatch call.

## Not exported: requirements for genuine support

- pcntl_fork: requires continuing in both parent and child from the same C/PHP instruction with copied address space, heap, stack and resources. CreateProcessW is not a fork. A separate Cygwin-linked PHP 8.5 interpreter now passes actual fork/exec and nested-fork conformance; the function is still absent from the native Windows DLL.
- pcntl_exec: POSIX exec replaces the current process image while preserving identity; ordinary Windows process creation makes a new PID. A separate Cygwin PHP build passed exec process-identity conformance; a Win32 supervisor handoff is not an equivalent contract.
- pcntl_forkx: Solaris-specific semantics and flags need a Solaris implementation or separately defined equivalent.
- pcntl_rfork: BSD-specific process and resource-sharing flags need a compatible BSD runtime.
- pcntl_unshare: Linux kernel namespace creation needs a Linux execution context for its guarantees.
- pcntl_setns: joining existing Linux kernel namespaces needs a Linux execution context; native Windows jobs, silos and containers do not transparently join Linux namespaces.

## Quality gates

1. Every new canonical PCNTL function must retain its documented PHP argument and return types.
2. Require a PHPT test demonstrating real Windows behavior and failure cases.
3. Compare result semantics to POSIX reference tests where relevant; label unavoidable divergence clearly.
4. Build and run PHPT on PHP 8.4 and 8.5, TS and NTS, x86 and x64.
5. Never export pcntl_fork as a CreateProcessW wrapper or a no-op. Do not fake namespace isolation or thread security guarantees.

## Alternate native POSIX runtime validation

- Cygwin PHP 8.5: [CI passed](https://github.com/MrPunyapal/pcntl-windows/actions/runs/42477101712) real fork/exec, nested forks, copied PHP heap, stream inheritance, and bidirectional inherited Unix socket communication. This separate Cygwin interpreter exposes 27 of 34 conditional PCNTL names and is not binary-compatible with ordinary Windows PHP.
- WSL2 Linux PHP: real fork/exec conformance is covered by tests/reference/fork-exec.php; Linux source-build CI also verified network namespace creation and joining when permitted.
- FreeBSD PHP: rfork is tested in tests/reference/rfork.php on a FreeBSD VM.
- Solaris/illumos PHP: [forkx conformance passed](https://github.com/MrPunyapal/pcntl-windows/actions/runs/42297736941) with PCNTL-enabled PHP 8.4 in a Solaris VM.
- macOS PHP: Apple QoS is validated in tests/reference/darwin-qos.php.
- Native Win32 helpers pcntl_windows_spawn, pcntl_windows_terminate and pcntl_windows_raise are not upstream PCNTL functions and must not be confused with true Unix process semantics.

See [CYGWIN.md](CYGWIN.md), [WSL.md](WSL.md) and [PLATFORM-REFERENCES.md](PLATFORM-REFERENCES.md) for runtime details. The native Windows DLL rejects overlapping PHP requests to prevent corruption of its process-wide signal queue; this is not concurrent ZTS support.

Windows group waiting: pcntl_windows_spawn($exe, $args, true) starts a new Win32 process group. The group id is the returned PID. pcntl_waitpid(-$pid, ...) and pcntl_waitid(P_PGID, $pid, ...) select only registered children in that group. pcntl_waitpid(0, ...) selects children spawned without the new-process-group option. This does **not** support POSIX setpgid, user process groups, or waiting for arbitrary external processes.
